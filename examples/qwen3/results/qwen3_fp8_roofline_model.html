Conclusion: theoretical limit ≈ 320 ms/step (FP8 GEMM compute wall). Communication is 90% overlapped (only ~7 ms exposed), not the bottleneck — the earlier "self-time sum ≈ wall → nearly serialized" was a misleading aggregation heuristic; trace interval union shows communication is well hidden. The real gap is non-GEMM compute serialized with GEMM (~232 ms, same compute stream) + bubbles (~52 ms). Next steps: ① reduce elementwise/copy volume (fusion); ② run non-GEMM compute in parallel with GEMM via multi-stream (hard); ③ tighten launch bubbles.
